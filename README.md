# 미슴도치 랜딩페이지

소개·Mac/Windows 다운로드·업데이트 내역·선택 이메일 구독 양식이 있는 반응형 웹페이지입니다. 아직 인터넷에 공개하지 않았습니다.

## 로컬에서 보기

Node.js 24 이상이 필요합니다. 별도 npm 패키지 설치는 없습니다.

```sh
npm run dev
# http://127.0.0.1:4173
npm test
npm run build
```

로컬 다운로드 링크는 보관함의 `Apps/DayColorShared/release/`에서 **site.json에 지정된 두 배포 ZIP만** 제공합니다. 개인 기록·백업·보관함은 제공하지 않습니다. `/api/subscribe`는 로컬 미리보기에서 항상 비활성화(503)되어 이메일이 전송되지 않습니다.

## 현재 완료 / 아직 안 된 것

- 완료: 미슴도치 이름, 두 플랫폼 다운로드 UI, 로컬 다운로드 연결, 반응형 디자인, 기능 소개, 업데이트 내역, 이메일 동의 양식, 서버의 동의 검증·Turnstile·Brevo DOI 연동 코드, 자동 비활성화 가드.
- 사진 아이콘: 사용자가 나중에 적용하기로 선택했습니다. 실제 사진 파일은 아직 받지 못했습니다. 현재 사이트 SVG는 임시 마크이며 앱은 기본 아이콘입니다.
- 미완료: 도메인/호스팅 생성, 배포 파일 외부 업로드, 이메일 계정·API 키·발신 도메인 인증, 실제 DOI 메일·구독 해지 검증, 운영자 정보·법적 고지 확정.

## 추천 공개 구조

1. **랜딩페이지: Cloudflare Pages** — 이 폴더만 별도 저장소/프로젝트로 배포. 앱·보관함 전체를 올리지 않습니다.
2. **앱 ZIP: Cloudflare R2 + 다운로드용 도메인** 또는 GitHub Releases — 현재 파일이 약 122/146MB라 Pages의 25MiB 단일 파일 제한보다 큽니다. ZIP을 Pages 정적 폴더에 넣지 않습니다.
3. **업데이트 이메일: Brevo** — 확인 메일(이중 동의), 수신 목록, 구독 해지와 캠페인 발송 관리.
4. **양식 보호: Turnstile + 서버 검증** — 프런트엔드 위젯만으로 처리하지 않습니다. `/api/subscribe`에는 추가 요청 제한도 운영 환경에서 설정하세요.

계정 비용·요금·무료 한도는 가입 시 최신 조건을 확인하세요. 여기서 계정을 생성하거나 유료 결제를 진행하지 않았습니다.

## 공개 전에 해야 할 일

- 사진과 이름의 공개 사용 권한 확인. 사진에 제3자 캐릭터/상표가 보이면 별도 확인하거나 대체합니다.
- `public/site.json`: 실제 HTTPS 다운로드 주소, 운영자 이름/문의처, 버전과 날짜를 설정.
- `public/privacy.html`, `terms.html`: 초안 표시를 제거하기 전에 실제 운영 정보·위탁·국외 이전·보유/삭제 절차를 확정하고 필요한 법적 검토를 진행.
- 로컬 Windows 테스트, 앱 서명·Mac 공증 및 공개 배포 경고 처리 검토.
- **API 키는 브라우저 코드/site.json에 넣지 않습니다.** Cloudflare 서버 Secret에만 저장합니다.
- 구독을 아직 운영하지 않을 때는 `newsletter.enabled=false`, 서버 `EMAIL_READY=false`를 유지합니다. 사이트와 다운로드만 먼저 공개할 수 있습니다.

`npm run build:production`은 실제 외부 HTTPS 다운로드 주소, 운영자/문의처, 개인정보 초안 해제를 확인하지 못하면 실패하도록 했습니다. 이 검사는 법률 준수나 서비스 정상 동작을 보장하지는 않습니다.

## 이메일 구독 연결

상세 안내: `EMAIL-SETUP.md`. 개략 흐름:

```text
방문자 선택 동의 → 서버 검증 → Brevo 확인 메일
→ 본인 이메일 확인 → 확인된 수신 목록 → 운영자가 업데이트 캠페인 발송
```

`functions/api/subscribe.js`는 Cloudflare Pages Functions 경로입니다. `lib/subscribe.mjs`를 함께 배포해야 합니다. Pages는 사이트 `dist/`와 루트 `functions/`를 처리할 수 있는 Git/Functions 배포 방식을 사용하세요. dist 파일만 다른 정적 호스팅에 올리면 API가 동작하지 않습니다.

공개 자산 빌드 출력은 `dist/`, API 코드는 `functions/`·`lib/`에 있습니다. 실제 `.dev.vars`·`.env`와 비밀 값은 Git에 커밋하거나 배포 자산에 넣지 않습니다.

## 새 버전 공개 순서

1. 앱 변경·호환성·백업 테스트 → Mac/Windows ZIP 생성.
2. 실제 OS에서 확인 → 버전별 파일명과 체크섬 유지.
3. **해당 ZIP만** 배포 저장소에 업로드. 개인 기록·개발 로그는 제외.
4. `site.json`의 버전·다운로드 URL, 화면의 업데이트 내역을 변경하고 사이트 재배포.
5. 확인된 구독자에게 업데이트 이메일 작성·검토·발송. 일괄 자동 발송은 현재 구성하지 않았습니다.

앱 자동 업데이트 설치는 별도 기능이며, 현재는 웹에서 새 버전을 내려받아 설치하는 방식입니다.

문서 근거: Cloudflare Pages Functions / Pages Limits / R2 Public Buckets / Turnstile Siteverify, Brevo Create Contact via DOI 공식 문서(2026-10-12 확인).
